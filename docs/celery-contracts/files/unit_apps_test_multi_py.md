### `t/unit/apps/test_multi.py`

Portable guarantee: this file covers `celery multi`, the launcher that starts, signals and tracks a cluster of named worker processes. For sqlery: a worker-pool manager must name workers predictably, give each its own settings, find them again through pid files, and handle dead or foreign processes without crashing.

**Worker-set specification**
- Spec "1-3" with range expansion on; expect workers 1, 2, 3. With expansion off; expect the literal "1-3". Mixed "1-3,10,11,20"; expect 1,2,3,10,11,20.
- Options scoped to specific workers (by name or index list) apply only to those workers; global options, valueless flags and everything after `--` (passthrough) stay separate and reach every worker.
- Ask for 10 workers with no names; expect 10 workers named base1..base10 on the current host, in order, each with its own pid and log file.
- Names given ("foo bar"); expect foo@host and bar@host. Explicit "foo@bar" is kept verbatim. Empty suffix gives "foo@". Prefix and suffix are applied to every name.
- A single name containing a dash ("worker-1") is one worker, not a range.
- Per-worker option beats the global one for that worker only; the others keep the global value. Index-scoped options work with named workers too (workers 1,2 get 10, worker 3 keeps 3).
- Index 0, or an index beyond the number of workers, raises an error naming the bad index (no silent ignore). A range that overshoots the count (1-5 with 3 workers) is tolerated and applies to the 3 that exist; a single out-of-range index still raises.
- A custom worker class supplied to the parser is used for every generated worker.

**Pid and log files**
- Pid and log path templates (%n, %i, %I, escaped %%) resolve to the same path the worker itself will compute; the manager finds a running worker's pid from that file, whether given as `--pidfile` or `-p`. Escaped percent signs survive as literal text.
- Defaults: pid and log go to standard run/log directories. A custom pid location creates its own missing directory and does not touch the default one.
- `~` in workdir, pid and log paths is expanded before use; directories are never created with a literal "~".
- A worker built from keyword options produces the right command line (app, queues, concurrency limits, pool options, executable, detach).

**Signals and process exit**
- Signal a worker; expect true. Process already gone (no such process) or not permitted; expect false, no crash. Any other OS error propagates.
- "Is alive" is a zero-signal probe and returns its result.
- Start a worker process; exit code 0 means success. Non-zero exit; failure hook called with the code. Killed by a signal; signalled hook called with the positive signal number.

**Cluster operations**
- Cluster reports its size and supports indexing; start launches every worker in order, firing start and status events for each, and passing spawn, signalled and failure hooks to each.
- Send-all signals each live worker, firing a per-worker signal event and a dead-worker hook for ones that cannot be reached. Kill sends SIGKILL to all.
- Reading pids: each worker's pid comes from its pid file; a missing or unreadable pid file reports that worker as down via the callback and omits it; works without a callback.
