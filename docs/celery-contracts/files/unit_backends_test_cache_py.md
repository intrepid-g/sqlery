### `t/unit/backends/test_cache.py`

Portable guarantee: a cache-backed result store keeps job state and results retrievable by job id, honours expiry, surfaces failures, coordinates fan-in of grouped jobs, and fails loudly on bad configuration. The memcache client wiring is Celery-specific; only its portable guarantees are listed.

**Configuration errors**
- Start the result store with no backend configured; expect a configuration error.
- Start it with an unknown backend scheme; expect a configuration error.
- Give the store an integer expiry of 10; expect the expiry to read back as 10.
- Report the store address: no servers gives `memory:///`; one server and several servers (semicolon separated) both round-trip exactly.

**Shared state**
- Write a value from a different thread through a second store instance on the in-memory backend; expect the main thread to read it back (state is shared, not per-instance).

**Job results**
- Look up a job that was never stored; expect state pending and result none.
- Mark a job done with 42; expect state success and result 42.
- Store a complex result (dict holding a custom object); expect it to come back intact (round-trips through serialization).
- Mark a job failed with a KeyError; expect state failure and the stored result to be that exception.
- Store two results and fetch both by id in one call; expect both returned.
- Store a result, then forget it; expect the result to read back as none.
- Run process cleanup on the store; expect it to be a harmless no-op.

**Grouped jobs / fan-in (dependencies)**
- Register a group of 3 jobs; expect the group to be restorable and equal to what was registered.
- Group of 2: the first member finishes; expect the callback not fired. The second finishes; expect the callback fired once with failure propagation and a timeout, and the group record deleted.
- Fan-in expiry rules: when a fan-in expiry is set it applies to the counter; the group record gets the fan-in expiry (600 with result expiry 100 or 86400 gives 600; result expiry 86400 keeps the job results at 86400).
- Fan-in expiry unset: counter and group fall back to the result expiry (100).
- Fan-in expiry 0: nothing expires (0).
- Result expiry none but fan-in expiry 600: counter and group expire at 600, job results never expire.
- On the final member finishing, expect the expiry of every member's stored result to be reset to the result expiry (100).
- Configure a fan-in expiry over 30 days; expect exactly one warning. At exactly 30 days; expect no warning.

**Client selection and options (memcache)**
- One server: expect the plain client. Several servers: expect the hash-distributing client.
- Retry attempts and delay configured: expect the client wrapped in a retrying client with those values.
- Retry-for and do-not-retry-for exception lists configured: expect them passed through unchanged.
- Legacy-library-only options (behaviors, binary): expect a deprecation warning and the option dropped.
- No options given: expect defaults that wait for server replies and set timeouts (connect timeout 5s).
- User supplies noreply, no timeout: expect their values win while untouched defaults remain.
- Legacy helper functions (best-client lookup, import-best): expect them to still work but warn.
- Servers none, empty list, or only blank strings: expect a configuration error.
- A trailing blank server entry (stray `;`): expect it ignored.
- A single address as a string or (host, port) tuple: expect it accepted.
- A non-string server value (11211 or [11211]): expect a configuration error.
- Memcache library not installed: expect a configuration error, not a crash.
- All backend names (memcache, memcached, pylibmc, pymemcache): expect each to resolve to a client.

**End-to-end with the memcache client**
- Store and fetch a result using a text job id; expect 42 back.
- Same with a bytes job id; expect 42 back.
- Retry options in backend settings: expect them reach the client (3 attempts, 0.1s delay).
- URL naming several servers: expect the hash client.
- Legacy `pylibmc://` URL: expect it still works, backed by the modern client.
- URL with no servers: expect a clear configuration error when the client is first used.
- Fan-in counter against strict client signatures: first member no callback, second fires callback and deletes group.
- Result expiry none: expect store, fetch and expire to work, with the expiry passed to the client as an integer (no type error).
- Worker startup info with several memcache servers in the result backend URL: expect it to start and report info without error.
