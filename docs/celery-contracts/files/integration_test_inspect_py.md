### `t/integration/test_inspect.py`

Contract for live worker introspection (inspect API): what an operator can ask a running worker, and what it must answer.

**Liveness**
- Ping the running worker; expect exactly one worker to reply "pong" (ok).
- Ask for the worker's logical clock; expect one reply with a value above 0.

**Registered jobs**
- List registered job types; expect a non-empty list of strings.
- List with detail "name"; expect each entry shaped like `name [name=name]`.

**Queues**
- List active queues; expect exactly one worker reporting the default queue with its full settings (durable, not exclusive, not auto-delete, no expiry/TTL/max length/priority cap, direct routing with key equal to the queue name).

**Running jobs**
- Enqueue a 5-second sleeping job, wait 1s, ask for active jobs; expect exactly that one job with id, name, args, kwargs, host, start time, acknowledged=true, delivery info (queue, priority 0, not redelivered) and worker pid.

**Scheduled jobs**
- Enqueue add(1, 2, z=3) to run 5s from now; ask for scheduled jobs; expect exactly that job with the exact run-at timestamp (UTC, microsecond precision), default priority, and a request that is not started, not acknowledged, with no worker pid.

**Query one job by id**
- Query an unknown (or already finished) id; expect an empty answer, not an error.
- Query an in-progress job id; expect state "active" plus its full details (same fields as the active list).

**Worker statistics**
- Ask for stats; expect concurrency 1, one pool process, uptime above 0, and the worker's own pid.

**Diagnostic report and secret hygiene**
- Ask for the report; expect an ok answer containing the software/version section.
- Result-backend URL with several memcached servers: the report shows it intact (no credentials to hide).
- Result-backend URL with several sentinel servers each with a password: no password appears; each is replaced by `********`, servers and db kept.
- Redis URL whose password contains commas and `@`: password never appears; masked as `********`.
- Redis URL with user and a password containing `,` and `@`: password masked, username kept.
- Whatever the report did, the original backend setting is restored afterwards.

**Revocation**
- Fill the queue with 4 sleeping jobs, enqueue one more, revoke it before it runs; expect its id in the revoked list.
- Another worker announces its revoked ids with timestamps far ahead of the local clock (longer uptime there); expect this worker to re-stamp them with its own clock (never trusting the remote stamps, which would never expire), so every stamp is at or before now; the reply carries ids only, as a plain list containing all received ids. Cleanup removes them.

**Configuration**
- Ask for config; expect one reply containing the key settings (logging, color, accepted content, UTC, timezone, broker url, result backend, heartbeat, deprecated settings, includes).

*Note: the Celery suite reruns each of these up to 5 times because timing-based; sqlery equivalents should wait on conditions, not sleeps.*
