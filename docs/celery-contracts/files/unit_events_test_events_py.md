Celery events are lifecycle notifications (job sent, received, worker heartbeat) published by a dispatcher and consumed by a receiver. Portable idea for sqlery: job/worker lifecycle notifications must never be lost, never crash the worker, and shut down cleanly.

**Event shape**
- Create an event of some type; expect: it carries its type and a timestamp.

**Transport / routing choice**
- Notification backend is Redis-like; expect: broadcast (fanout) routing. Any other backend; expect: topic routing.
- Dispatcher built from an existing channel; expect: it reuses that channel's connection.
- Backend is a SQL database transport; expect: notifications disabled automatically.

**Sending**
- Enabled, send one notification; expect: delivered. Disabled, send one; expect: dropped, nothing delivered.
- Publish fails, buffering off; expect: error raised to the caller.
- Publish fails, buffering on, send 3 notifications; expect: all held; after the outage ends and flush runs, all 3 delivered; a second flush does nothing.
- Dispatcher closed (sender cleared) but still marked enabled, a stale timer sends a heartbeat; expect: silent no-op, nothing buffered, no AttributeError.
- Failed publish buffered; expect: buffer entry holds only event and routing key, no exception or traceback (avoids memory leaks in long-lived workers).
- Replay after outage with 3 buffered events; expect: all delivered, buffer empty.
- Replay itself fails; expect: event stays buffered, next flush after recovery delivers it, buffer empty.

**Batching (group buffer)**

- Batch publish fails, buffering off, 2 events held; expect: flush raises, both events stay in the group buffer (not dropped, outbound buffer empty); after recovery next flush delivers both in order, buffer empty.
- Events appended while a batch is publishing; expect: published batch is only the earlier ones, late arrivals stay buffered.
- Events appended while a publish then fails; expect: all original plus late events remain, in order.
- Flush with both errors and groups switched off; expect: nothing happens, no error.
