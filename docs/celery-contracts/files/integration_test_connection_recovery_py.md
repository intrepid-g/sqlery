### `t/integration/test_connection_recovery.py`

Portable guarantee: when the database connection goes silent (no error, no close, e.g. suspended VM or firewall dropping the flow), worker recovery and shutdown must finish in bounded time and never hang.

**Reconnect after a silent connection**
- Worker holds an open DB connection with a claim/poll query outstanding; the database goes silent (no reset, no close). The worker hits a connection error; expect: the error handler returns within a fixed deadline (a few times its own timeout), never hangs.
- Same scenario; expect: the broken connection is released (worker's connection reference cleared) before the worker restarts its loop, so a fresh connection is made.
- The handler must not "finish fast" by crashing: only a timeout error from the silenced peer is tolerated; any other exception fails the contract.

**Cold (immediate) shutdown with a silent connection**
- Worker told to shut down immediately while its connection is silent with a poll outstanding; expect: closing the connection returns within the shutdown deadline, no hang.
- Socket timeouts are applied to already-open connections at shutdown (setting a default timeout only affects new connections, so it is not enough).
- Warm (graceful) shutdown deliberately does not bound the close, because it still has acks/results to flush.

**Test hygiene guarantees**
- A killed database is not a valid simulation (it sends close/reset and returns instantly); the silent case must be simulated with both sockets held open and no bytes relayed.
- Poll interval is long, so no reply can already be buffered when the peer goes silent.
- Connection credentials, db index and options survive when redirected through the proxy.
- Test applies only to plaintext TCP redis; skipped for TLS or unix-socket brokers.
- After each test, wedged connections and sockets are force-dropped so they do not leak.
