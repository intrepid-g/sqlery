### `t/unit/backends/test_rpc.py`

Portable guarantee: the RPC backend returns results over a per-client reply channel (no DB). The portable contract is: result delivery survives connection loss, each result is consumed exactly once, nothing leaks or recirculates, and unsupported features fail loudly.

**Result listener: connection loss**
- Wait for results before the listener has started; expect: no crash.
- Connection drops mid-wait; expect: old connection closed, new one opened, listening resumes, no error raised.
- Reconnect after a drop; expect: every previously subscribed queue is re-subscribed.
- Connection-level and channel-level errors both trigger a reconnect.
- Plain "no result within timeout" while waiting; expect: timeout surfaces to the caller, no reconnect, connection left open.
- Unexpected non-connection error while waiting; expect: propagates, no reconnect.
- Closing the old connection or cancelling the old consumer fails during reconnect; expect: failures swallowed, new connection still established.
- Connection drops and reconnecting also fails; expect: a "retry limit exceeded" error, not a hang.

- Declaring a reply channel for a job is a safe no-op-style interface call.

- Submitting a job declares the reply queue, with retry.
- Reply exchange is the default (unnamed) exchange.
- Reply destination comes from the job request; with no request it falls back to the currently running job; with neither, expect: error.
