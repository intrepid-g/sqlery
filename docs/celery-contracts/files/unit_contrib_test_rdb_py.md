Celery's remote debugger (rdb) lets a developer attach to a running worker task over a TCP port. Only the portable guarantees are listed; sqlery's equivalent is an optional remote debug hook for a job running inside a worker.

**Debugger lifecycle**
- Ask for the debugger twice in the same worker; expect: the same single debugger instance both times (no second listener).
- Call set-trace from inside a job, with or without an explicit stack frame; expect: the debugger is started and breaks in at the caller's frame.
- Start a debug session; expect: the worker announces the host/port to the log or output stream, waits for one client, and shows the client's address once connected.

**Port selection**
- Start a session with no port configured; expect: a free port is found and bound.
- Start a session from a pool worker named like "PoolWorker-10"; expect: the port is offset by the worker's index so concurrent workers do not collide.
- Port already in use, with other free ports above it; expect: the next ports are tried in turn and a free one is eventually used (even after 50+ failed attempts).
- Port already in use and no free port found; expect: a clear error, not a hang.
- Binding fails for any reason other than "address in use" (e.g. missing path); expect: the original error is raised immediately, no retries.

**Controls and error handling**
- Client issues "continue"; expect: the job resumes normally, tracing stops.
- Client issues "quit"; expect: tracing is switched off (trace hook cleared) and the job is released.
- The debugger's own set-trace raises a socket error other than a benign disconnect; expect: the error propagates to the caller.

**Cleanup**
- Close the session twice in a row, or with the client, handle and socket already gone; expect: no error, nothing left open (idempotent cleanup).
- Leave the debug context normally; expect: sockets are closed and the session is marked inactive.

*Portability note:* purely a developer-tooling feature; sqlery only needs the generic guarantees of no port collisions between workers, bounded retries with a clear failure, and idempotent cleanup.
