# What sqlery must guarantee: the contract of a reliable cousin of Celery

**Goal.** Sqlery should know what is expected of a reliable cousin of Celery. This is the plain-English "contract" distilled from Celery's own test-suite (`celery/celery`, `t/unit`, `t/integration`, `t/smoke`; 180 test files, one Sonnet agent per file). Vendor wiring (RabbitMQ, Redis pub/sub, Mongo drivers and so on) is dropped; what is kept is the assurance, the edge case, and the way unexpected trouble is handled.

**Style.** Each line is a scenario: set-up, then "expect". Examples: *"Enqueue 2 jobs, run the worker; expect 2 done, queue empty."* / *"Enqueue job 1, job 2 (raises), job 3; expect job 1 done, job 2 failed, job 3 per its dependency rule."* Celery terms are translated: chain = dependencies, group = sibling jobs, chord = job that waits for N jobs, errback = on-failure follow-up job, stamp = job metadata/tag, revoke = cancel, eta/countdown = run-at/delay, broker/result backend = the database.

**Detail.** Every file's full scenario list is posted as a comment below (one per source file). Each section names the files it draws from. This body is a condensed merge (GitHub's 65k-character limit): the per-file comments below hold the full scenario lists, including finer edge cases omitted here. Cross-cutting themes are in section 14. Tip from the suite itself: wait on conditions with bounded timeouts, never bare sleeps; every wait has a deadline and a clear failure message.

## 1. Task execution, enqueueing and results
*Sources: integration/test_tasks, unit/tasks/test_tasks, unit/tasks/test_result, unit/tasks/test_context, unit/worker/test_request, ...*

**Basic round trips**
- Call a job function directly: it runs inline and returns the value. Enqueue 10 jobs with positional args, then 10 with kwargs, run the worker; expect all done with correct results, each reporting success/ready/successful. Unicode outputs (5 at once) succeed. Custom message properties are visible to the job.
- Many producers (20 threads x 20 jobs, 42 threads with a raised pool limit): every enqueue succeeds with its own result, no pool exhaustion or deadlock; the "job enqueued" hook fires once per enqueue; each thread sets up its own context.
- Empty-options enqueue must not leak or cache a job-type default such as "discard result": job A by name, A with empty options, job B all still return results.
- Run inline (eager): finished result, successful, ready; a raising job is ready, not successful, traceback stored, get re-raises (or raises at once with throw/propagate). Context says is_eager; a lone job has no parent and root = own id; nested calls get parent = caller, root = first. Eager results are stored only if "store eager results" is on.

**Bad input is rejected at enqueue time, nothing queued**
- Missing or unknown arguments: immediate TypeError. With argument checking switched off (per job or globally) it is queued, the worker runs it, and it ends failed with TypeError.
- kwargs not a mapping, args a bare string or not a list/tuple: TypeError. Negative delay: ValueError. Arguments the configured serializer cannot encode (a set under JSON): encode error up front, also in eager mode; accepted if pickle is allowed.
- A job subclass without a body raises NotImplementedError. Per-job option overrides (by name, wildcard "*", dotted-path rules, None config) apply; an absent override gives nothing, not an error. Jobs are callable, pickle back to the registered job.
- Typed (validated) arguments: coercible input accepted in non-strict mode, rejected in strict (ValueError, body never runs); model objects converted to plain dicts before sending; values that cannot be dumped faithfully fail at enqueue time; missing validation library = config error with install hint.

**What is stored at enqueue**
- Job id, name, args, kwargs; ETA and expiry as ISO timestamps (absolute aware, naive treated as UTC, in the past still stored, relative seconds). Success/failure follow-ups and a final "wait for all" step are stored in order.
- Args/kwargs display text defaults to repr but the caller can override with redacted text (`'***'`) so secrets stay out of logs and dashboards.
- Display previews of nested args are truncated past a configurable depth (`{...}`), deeper if raised, unlimited if 0/None; same for kwargs.
- Priority resolution: app default, job, base class, per-call; priority 0 is honoured (not "unset"); child may inherit parent priority when configured. Custom display ("shadow") name function is honoured.
- Ignore-result: per-call beats job beats app default (both directions); cached execution options are never mutated by a call.
- Purge queue returns the count removed and leaves it empty.

**Results and result handles**
- Unknown id: state pending, result empty, no traceback, not ready, not successful, `exists()` a real False. Stored done/failed/retrying: `exists()` True. Done with None returns None and is still done (not pending). Ready = done or failed; retrying and pending are not ready.
- Failed job: get re-raises the same exception type with original args; remote traceback frames only if enabled; with propagate off the exception is returned as a value. Retrying job: result is the exception, not ready, short-timeout get raises timeout (even when poll interval > timeout). Pending job get with short timeout raises timeout; the waiter times out, the job is unaffected.
- Ignored-result job: get returns None immediately. Calling get from inside a running job is refused (would deadlock) unless the guard is explicitly disabled. Child of a failed parent: get raises the parent's error without waiting.
- Request metadata (name, args, kwargs, worker, retries, queue, date done) readable from the handle; date done is None while retrying, a datetime in the configured zone when finished. Handles are equal by id, pickle/copy, and dropping one unregisters it without error.
- Result sets: idempotent add, harmless discard, adding to a complete set makes it not ready again; completion callbacks fire once (immediately if already complete); join timeout 0 is non-blocking; nested groups to any depth, failures as values with propagate off, raised with propagate on; forgetting a group forgets every member; group save/restore round-trips, deleted group restores None.
- Eager results: wait raises or (propagate off) returns the error; revoke returns False, state revoked, get raises "revoked"; revoking a failed job replaces its error, revoking a done job discards its value; copy/pickle preserve everything.
- Result store with results disabled: jobs still enqueue and run; asking for a result gives a clear "not supported" error, never a wrong answer; failing a chain with an error callback works without reading stored state (no NotImplementedError, no worker crash), the callback runs exactly once; outcomes are observed via side effects.
- Polling status is idempotent and side-effect free: poll a finished job 5 more times, still success, served from cache; the store holds 0 leftover ready messages (regression #4830).

**Per-job context**
- Declared stamps travel into execution options, undeclared ones do not, and a stamp named like a system field (`retries`) cannot override it. A fresh job context shows defaults with no leakage between jobs; time limits unpack from dict/pairs/kwarg and None clears both.

**Logging and hooks**
- Successful job logs "received" then "success" (info); failing job "received" then "failure" (error), using the custom display text.
- Hooks: two listeners both see the job id, disconnecting or GC'ing one leaves the other; before/after-publish handlers have run when enqueue returns; a faulty sent-signal receiver never stops publishing; sent-event publish failure with retries 0 doesn't retry and the job still completes. Success logs "received" then "success" (failure: "received" then "failure"), using redacted display text.
- Arg/result preview text is bounded and never crashes: self-reference prints "Recursion on", a failing repr prints "Unrepresentable", truncation keeps brackets balanced at every limit, depth overflow gives a placeholder.

## 2. Failure, retry, timeouts and error storage
*Sources: integration/test_tasks, test_mem_leak_in_exception_handling, unit/tasks/test_tasks, test_trace, unit/app/test_trace, ...*

**Failure**
- Job raises: the original exception type reaches the caller, status failed, ready, not successful. Unpicklable exception: error still retrievable with class name and args; a class whose serialization raises falls back to generic Exception; job marked failed, not crashed. Extra constructor args and attributes round-trip.
- Stored error naming something that is not an exception (`os.system`, `builtins.object`): SecurityError, never executed. Class gone or constructor arity changed: readable fallback, no crash.
- Outcomes: ordinary exception = FAILURE with traceback cleared; Retry = RETRY; Ignore = IGNORED (result None, chain stops); Reject = REJECTED (chain stops); SystemExit propagates (worker may shut down) and is not stored as a failure. Expected "throws" logs as expected, others as unexpected.
- Memory: 500 failing jobs, 100 retry-then-fail jobs, 200 deeply nested failures: frames and locals released, memory growth bounded (about 10% / 3 MB / 4 MB), traceback text still reportable, healthy jobs afterwards unaffected. Clearing never crashes (never-raised exception, still-executing frame).
- Hook failures never corrupt the outcome: an on-success hook raising after the result is stored leaves SUCCESS (error logged; propagates in eager mode); Reject and MemoryError from hooks are not swallowed; after-return hook raising on a failed job records the failure once. Result-store failure on both writes rejects the message (acks-late) so it is not lost; an error escaping the tracer is an internal error and the tracer is reused.

**Retry**
- max_retries=3 always retrying: 4 runs then failure; per-call override 10 gives 11; "max retries exceeded" failure carries original args/kwargs; custom exception surfaced; max_retries=0 gives 1 run; a lower limit set at retry time wins; unserializable exception gives a safe wrapper keeping class name and args.
- Eager retry re-runs and returns the final value. throw=False vs True: both schedule a new run, only True raises the retry signal. Retry arguments: new positional args, new kwargs (override matching parameters of any kind), nothing = original reused, both = exactly those; caller's kwargs never mutated; unmatched kwargs or uninspectable signature pass through.
- Retry copies headers, delivery info, priority (7 in, 7 out) and display name, drops dead-letter bookkeeping headers (x-death...), and a retried job with expiry 60 still completes. Retry state is visible, then failed at the limit; retry-then-succeed returns the value; a once-retried job records exactly one retry. A delayed retry re-queued to the same queue (3s, once or twice) is never lost or rejected and retry count stays accurate.
- Auto-retry on listed exceptions (inheritable, overridable): retries to the limit, unlisted errors not retried; exponential backoff 1,2,4,8 (factor 2 gives 2,4,8,16; False/0 no delay); cap (1,2,4,8,16,16); jitter random in 0..computed; shared settings dicts never mutated; class-based jobs same; non-UTC clocks give correct ETAs.
- Redelivery after rejection: reject with requeue succeeds on the second pass. Reject without requeue = failed with reject error.

**Time limits**
- Soft limit greater than hard limit: rejected immediately ("soft_time_limit must be <= time_limit"), nothing queued. Limits at enqueue are visible to the job; none = both None; declared on the job used; enqueue-time wins; app-wide limits fill only when the job has none. Backoff: retry 3 factor 4 = 32s, capped at maximum, negative factor = 0.
- Soft limit exceeded: catchable "soft time limit exceeded", caller sees failure, nothing stored yet, not acked. Hard limit exceeded: child killed and replaced, TimeLimitExceeded stored; late ack acks; ack-on-timeout true acks, false rejects with requeue; failure hook/signal/event and after-return hook fire; no traceback retained; worker still runs trivial jobs afterwards.

**Worker crash isolation**
- SIGKILL inside the job, hard exit(1): "worker lost" error to caller, new child process spawned, pool size normal; log says "exited prematurely" with signal 9 / exitcode 1.
- Late ack + reject-on-worker-lost + retry-on-worker-lost: a job always SIGKILLed is received 3 times, retried exactly 2, then fails "worker lost" (no infinite loop). Retry re-enqueues with count+1 and delay, stores retry state, fires events/hooks, acks the original; exhausted retries fail and ack; if re-enqueue fails, fall back to reject-and-requeue (or store failure if reject-on-lost is off).
- Worker lost but success already stored (child finished then died): keep SUCCESS, no failure, no error callbacks, no requeue, succeeded event, ack. Check skipped when result ignored or backend cannot be queried; if the lookup errors, treat as failure.
- Job calling exit (SystemExit/KeyboardInterrupt) = worker lost "exited prematurely"; late ack acks, reject-on-lost requeues. Failure caused by our own terminate/cancel, or during worker shutdown, stores no failure and leaves the message unacked for redelivery.

**Expiry**
- Job expiring in 1s behind 4 slow jobs (relative or absolute): skipped, status revoked, not failed. No expiry never expires. Past expiry: marked revoked, in revoked set, revoke signal expired=true; ignore-result: revoked but nothing stored. Exactly at expiry is NOT expired, one microsecond later IS (also across DST fall-back). An expired job dispatched to the pool raises revoked instead of running. Malformed ETA/expiry or invalid structure: rejected as invalid job.

## 3. Delivery guarantees, acknowledgement and duplicates
*Sources: unit/worker/test_request, smoke/test_dedup_chain_dispatch, test_worker_shutdown_acks, unit/tasks/test_trace, ...*

- Early ack (default): acked when accepted by a pool process. Late ack: acked after success or failure (and on retry). Ack is idempotent; reject after ack is a no-op. Ack-on-failure true acks, false rejects without requeue; separate from ack-on-timeout; legacy combined flag resolves into both; a raising ack callback is logged, not propagated.
- Duplicate delivery (dedupe on, late ack): a redelivered job whose result is already SUCCESS is skipped (first run 2, second nothing) but its downstream work is not dropped: follow-ups and the next chain step are dispatched exactly once with the stored result (parent id = job id; chain remainder passed; nothing re-sent if children already recorded). If dispatch fails (broker down, backend read fails) the message is rejected for requeue and the id is NOT marked successful, so it is retried. Dedupe off: redelivered job runs normally; stored state not SUCCESS or "not found": job runs.
- Late-ack redelivery after reject/requeue completes the chain with the second run's value.
- A job that finishes during shutdown is acked immediately (not deferred), so a later hard kill cannot re-run it; only genuinely in-flight jobs are returned to the queue (exactly one in the 420s/3s scenario).
- Duplicate reports for a group member (redelivered after worker lost): recorded once, first value wins, final step runs once (see 9).

## 4. Workers: startup, shutdown, connection loss, claiming, liveness
*Sources: integration/test_worker, test_connection_recovery, smoke/test_worker, test_worker_shutdown_acks, test_consumer, ...*

**Startup**
- Database unreachable with startup-retry disabled: exit status 1 with a clear message (fail fast, no hang). Startup retry setting: "retry on startup" with max 7 retries retries 7 times; disabled = one attempt; unset falls back to the legacy setting (deprecation warning if that is off); explicit on beats legacy off; "off" affects only the first connect, later reconnects retry. Failed startup exits non-zero.
- Components start in dependency order, stop/terminate tolerate missing parts, disabled components are not created, a failing component during broadcast is swallowed (or raised if propagate) and the rest still run. Worker name is `name@host` (default only when missing).
- Worker emits "ready" once; polling uses bounded waits so a stop request is noticed; a pool that fails to start raises worker-lost. Pid file lock created on start, released on stop; optional state file persists the revoked list.

**Claiming (prefetch) and capacity**
- Claim limit = concurrency x multiplier (derived from configured concurrency, never from "jobs running now"). "Disable prefetch" mode: a worker with all slots reserved refuses another claim; with 2 of 4 busy and work available it claims one; honours autoscale max when lower; a no-op on backends where it does not apply. A held (not-yet-due) job increases capacity by one so it does not starve others, then decreases when released.
- After connection loss with reduction enabled and N jobs running: claim limit drops (never to 0, e.g. max(2, 10-2N)), is logged with the reason, restored gradually as jobs finish, then logs "normal operation resumed" at the maximum. Idle worker keeps the full limit. Reduction disabled: limit stays full and a quick job waits for a slot (no over-claiming). Per-consumer-limit backends skip the reduction and log it; a stale reduced value resets to full.
- Cancel-on-connection-loss (late ack): unacked in-flight jobs cancelled and slots freed, redelivered; acked and early-ack jobs untouched; a raising cancel is swallowed; succeeded jobs never cancelled. A new quick job must complete afterwards (no deadlock from originals plus redelivered copies). Count N in-flight occurrences, don't just detect the first; poll a window for "never appears". Test several workers claiming concurrently (untested upstream).
- Rate limits: a type limited to 1/min is deferred to the limiter, not reserved; capacity available = straight to the pool; none = retry after the expected wait; with eta, scheduled first then limited; disabled = reserved at once. Rate strings ("100/m", 7.5) normalise to per-second; 0/None = no limit, never a divide error.
- Scheduled (ETA) jobs are findable before their time but not in the reserved set; the timer entry is attached before the job is visible as scheduled; non-UTC timestamps OK; overflowing ETA rejected without requeue with failure recorded (or tolerated when storing is disabled). Revoked-on-arrival jobs discarded. Unknown job name: rejected and logged; invalid message: logged and worker continues; undecodable message: acked (not redelivered forever) with a critical log; reject failing due to dropped connection: warning, nothing run. Legacy-format messages convert (empty args, retries 0, custom headers kept, non-mapping kwargs rejected).
- Lifecycle tracking: active jobs counted per name; scheduled to reserved moves between sets; a scheduled job that finishes/cancels is forgotten; a job already reserved/active then marked scheduled is a no-op (shutdown cleanup can never drop a running job).

**Connection loss, reconnect, failover**
- Silent connection (no error, no close): the error handler returns within a few times its timeout, releases the broken connection before restarting, tolerates only a timeout from the peer. Cold shutdown closes within the shutdown deadline; socket timeouts are applied to already-open connections; warm shutdown deliberately does not bound the close (acks must flush, else jobs run twice). Teardown never reconnects.
- Store goes down: worker keeps retrying with growing back-off (e.g. 8s on 4th of 100) and logs each attempt; after restore a group of 5 and a chain of two 5-job groups complete (dependencies honoured after an outage). Too many restarts in a short window: sleep 1s. Out of file descriptors: terminate. Connection error always restarts; channel error only if enabled. Dead-connection cleanup always runs with a socket timeout. Retry disabled + lost: shut down with a critical log naming the setting. Each retry logs "trying again in X seconds (n/max)".
- Cleanup on reconnect: timers registered by the lost connection are cancelled (no accumulation over repeated reconnects); the worker's own timers and running jobs' time limits survive; one failed cancel doesn't stop the rest.
- Failover: two endpoints; kill primary, next job runs on the standby (worker logs the retry with masked URL); kill standby, restart primary, next job runs on the primary. With late ack, killing a worker doesn't lose its job: it completes; kill all, restart one, job completes. 5 erroring broadcast control commands don't crash the worker (ping pong, add(4,4)=8).
- Heartbeats: online event at start, heartbeat each tick, offline on stop (retry off so shutdown can't hang); periodic events use retry; disabled events send nothing. Frozen worker: heartbeat connections dropped within ~5x interval, its row marked stale/dead, its running jobs detected as orphaned and recovered (requeued or failed); a regularly heartbeating worker stays alive and keeps leases. A draining worker (10s job, 2s heartbeat) keeps heartbeat/lease alive: no "missed heartbeats", job acked not requeued (queue ends 0 total/ready/in-flight).

**Shutdown**
- Warm stop (SIGTERM): finish the running job then exit, repeats harmless. Cold stop: job not completed, worker exits. Warm then cold twice, or cold twice, on a 420s job: forced exit without waiting. Remapped stop signals behave the same.
- Soft shutdown grace: 10s grace, 5s job, cold signal: "soft shutdown" announced, job finishes in grace, success; 420s job with two cold signals skips the wait; waits only if jobs run (or soft-shutdown-on-idle). Grace 16s, hard limit 15s: 8s job finishes without a hard-limit error.
- Unfinished work returns to the queue: soft-shutdown expiry puts a 15s job back ("1 unacknowledged restored"); group of 3s + 15s restores only the unfinished; two 15s jobs restore both and after restart group result is [true, true]; a not-yet-due delayed job is put back (1 restored) and runs after restart.
- Signal handling: a warm signal with banner printing raising still sets the stop flag; a cold one with callback raising still sets terminate (not yet set while the soft-shutdown callback waits); signals in a child pool process print no banner but set the flag; stop flag with exit code exits with it; terminate beats stop.
- Warm shutdown must not lower the socket timeout; cold/terminate bound it by the shutdown timeout; cold with consumer cancel timing out still cancels active requests and sets terminate. Close clears semaphore/reserved set, removes reserved-never-started and scheduled jobs from the registry and cancels their timers (failure logged, cleanup continues); a job both running and scheduled stays visible as running. 3 jobs of 10s with 2s heartbeat and graceful stop: connection kept, all succeed.
- A crashing helper thread logs and exits the process with status 1 (no zombie worker). Pool restart mid-job (late ack) still completes.
- Queues: consume by alias + default; cancel by alias stops consuming and is NOT resumed after forced reconnect; cancelling an unknown queue never creates it; re-adding restores consumption.

**Misc**
- Spawn mode: job runs in a spawned child; 30s job with 3s hard limit fails then a 1s job succeeds. Start method defaults to fork, accepts spawn, rejects others. Concurrency option: "4", "auto" (any case), empty/"0" fall back to default; "garbage" and negatives rejected with a message mentioning "auto".

## 5. Concurrency pools and sizing
*Sources: unit/concurrency/* (concurrency, eventlet, gevent, pool, prefork, solo, thread), smoke/test_autoscale, test_concurrency_auto, ...*

- Running a job in a slot: accepted handler fires first (pid, start), then the job, then the completion handler with the result; ordinary errors, shutdown and terminate requests propagate; a non-standard fatal exception becomes a failed result; if re-raising it also errors, that error surfaces and the completion handler is NOT called.
- Pool of 2: job A (100), B (raises, returns captured exception info), C (400): callbacks fire once each in completion order, original exception type and message kept, pool keeps working after a failure. Pool of N reports concurrency N; start/stop/terminate/flush hooks are harmless no-ops by default; restart or terminate-by-id with no implementation = "not supported". Thread-less platform lists no threads pool.
- Solo pool: starts with no setup, runs inline, announces "process initialised" exactly once with the hostname. Thread pool: stop rejects later submissions, cancels queued jobs while the running one finishes, is idempotent, leaks no threads.
- Prefork: child startup resets signals, fires init event, sets title, dies if parent dies; child exit emits shutdown event with pid/exit code. Dispatch robustness: poll EINTR keeps descriptors, EBADF drops them, others propagate; unwritable input pipe (100+ EAGAIN) logs "Process inqueue damaged", terminates child, requeues the job for redispatch; ack for vanished child discarded. Flush on reconnect: unaccepted jobs discarded/cancelled, accepted untouched, dead-child writers dropped (no infinite loop), half-done ack writes completed (else child hangs), a child with an accepted job stays busy, partial result reads completed without blocking, stalled/dead/EOF child drops descriptor with one warning. Shutdown tolerates truncated messages; restart/stop/start/terminate repeatable; grow/shrink (10, 11, 9) reports correct sizes; child liveness timeout default 4s.
- Eventlet/gevent: runtime patched before job code; resize works (blocked job starts after grow); autoscaler scales from capacity; killed job gives a no-result outcome not a crash; finished jobs leave the tracking map; timers cleared even if a cancel raises.
- Autoscale (min 3, max 10): idle 3; 20 reserved = 10 (never beyond); shrinks only after keepalive since last activity (job at t=200 restarts the clock; keepalive 30 shrinks at t=231); size always within [min,max]. Smoke: burst of 2 grows to exactly 2 processes; 3 more bursts with gaps shorter than keepalive keep the same 2 processes (no churn). Runtime max/min change resizes and adjusts prefetch by the delta. Receiving a job never blocks on a resize; scaler crash exits with 1; shrink errors swallowed.
- Auto concurrency sizes from the CPU budget actually allowed: min(CPUs, quota); 2-CPU quota gives 2; 0.5 gives 1 (never 0); no quota falls back to CPU count with a log; pinned to one core gives 1; quota 1.5 on 8 CPUs rounds up to 2; quota above CPUs capped; threads/solo/gevent/eventlet not capped (logged); an explicit number always wins; "auto4" is not auto. Quota lookup (cgroup v1/v2): none/"max"/-1 = none, fractional honoured, smallest along the parent chain wins, garbage/unreadable files = no quota without exceptions, no endless loop on odd paths; unknown CPU count defaults to 2.

## 6. Scheduling (beat), time and time zones
*Sources: integration/test_beat, smoke/test_beat_remote_control, test_beat_shutdown, unit/app/test_beat, test_schedules, ...*

**Due-ness**
- Interval: 10s last run 10s ago = due (next check 10s); 3s ago = not due, 7s left; 0 or negative = due with wait 0, never negative; relative 1s capped at 0.25s; late hourly run: relative realigns (30s), non-relative keeps drift (3600s).
- Real elapsed time decides, across DST (fall-back hour not run twice, spring-forward hour skipped) and odd zones (Lord Howe 30-min shift, Havana midnight gap, Kathmandu, Samoa skipped day, Kwajalein 23-hour day, Goose Bay repeated midnight), zoneinfo and dateutil identical. Wall-clock daily runs at local midnight (first valid time after a gap, once for a repeated midnight); elapsed-time daily runs 24 real hours apart.
- Cron: `*`, ranges, lists, steps, wraparound (`11-1`), names (`mon-fri`, `aug-oct`); bad input rejected at creation (empty items, `*/`, out of range, unknown names); impossible dates (Feb 30, Apr 31) rejected, Feb 29 accepted; needs 5 fields; equal specs written differently compare equal. Next run: minute/hour/weekday/month/day math, day-of-month AND weekday both must match (searches ahead; impossible = RuntimeError, no endless loop), 09:00 Paris stays 09:00 across DST, last run in another zone converted first, long-missed slots returned as already past (due).
- Missed-run catch-up: no starting deadline = due at once; with deadline 1h a missed slot older than that is skipped, within it (or exactly at it) runs, also for irregular schedules (:00, :45) and across DST; last run in the future or at/after the latest slot = not due (no double run). After restart, tasks missed 2 minutes ago run once each.
- Solar: missing optional dependency = clear config error; invalid latitude/longitude/event = ValueError; polar-night days skipped with a bounded search; due at sunrise exactly once.

**Scheduler loop (tick)**
- Tick: due task dispatched (returns 0); not-due returns slightly under remaining; sleep never exceeds max interval; top-of-heap not due with a due task behind: pushed back, due one next tick; if a due-check mutates the queue nothing stale is dispatched; replaced task uses its new interval; freshly loaded schedule merges (removed gone, new appear).
- Tick failures: enqueue error logged and tick returns normally; a task whose next-run calc raises is logged by name, pushed back by max interval and never dispatched while healthy tasks still run.
- Dispatch: None args/kwargs treated as empty; tagged as from the scheduler with caller headers preserved; countdown/options forwarded; sync every N dispatches saves the schedule.
- Shutdown releases connection, channel and handles, syncs and closes the store; second close no-op; failures during sync/release never leave resources open (sync error wins); reuse after close creates fresh handles; thread exits within 5s with socket closed even while references are held; two start/stop cycles each deliver their own payload with no leaks.
- Service lifecycle: serialisable (a spawned child must not re-enable control); SystemExit in a tick shuts down cleanly; embedded mode forces remote control off unless overridden; launcher passes options faithfully ("unset" = None, not False); CLI failure exits 1 with banner (quiet hides banner, not exit code).
- Liveness endpoint: off by default; ping replies pong; stall threshold defaults to twice the loop interval (0 disables); a stale or wedged scheduler gives NO reply plus one warning and recovers on a fresh tick; messages for other nodes and worker-only commands get no reply; handler exceptions swallowed; start idempotent, stop twice no-op; unsupported transport refuses to start with one warning; reconnects after drop; exhausted retries give up once naming the settings; stop during back-off interrupts promptly; worker and scheduler coexist on one channel.

**Time arithmetic**
- Add 90 minutes across spring-forward = 90 real minutes, same across fall-back and in the repeated hour; naive = wall-clock addition. Subtract = real elapsed across DST/zones, negative allowed, naive treated as UTC. Nonexistent local time (02:30 spring-forward) moves to 03:30; localise is idempotent; half/quarter-hour offsets exact (-5.5, -5.75).
- ISO 8601: Z = UTC, offsets preserved, microseconds exact, date-only = naive midnight, impossible values rejected, junk gives "unable to parse date string". Quirks NOT to copy: garbled offset silently ignored; compact form crashes with a type error.

## 7. Queues, routing, priority and delayed delivery
*Sources: unit/app/test_routes, test_amqp, smoke/test_task_queue_*, quorum_queues/*, integration/test_tasks, ...*

- Routing at enqueue: static table (name to queue or full destination, bare string = queue, globs first-match-wins, regex keys, no match = default); missing queue with auto-create off = clear "queue not found"; several rule sets: first match wins; function routers get (name, args, kwargs, options, task), returning nothing = no opinion; legacy `route_for_task` works; explicit queue with None extras keeps the queue; rules cached, rebuilt once on runtime change.
- Queue defaults: a job sent to a named queue with no default configured runs there; queues created without override inherit system defaults (exchange, routing key, max priority) whichever API registered them; alias or real name finds the same queue; invalid auto-create type = ValueError.
- Delayed jobs: 5s delay not early; ISO due time; due in the past, delay 0 or negative = immediate; 25-hour delay stays pending; 5 or 100 jobs due at the same instant all run (100 within 10s, none lost); due at +2/+4/+6s complete in order; 3-job chain each delayed 2s ends 10; delay then cancel: pending, then revoked, never runs. ## 8. Result backends / storage

## 14. Cross-cutting principles the suite keeps proving
1. **Nothing is silently lost.** Undecodable, unverifiable, expired, unroutable or crashed-worker jobs end as a visible state (failed, revoked, rejected) or are redelivered; a caller waiting on one never hangs.
2. **Final states are sticky.** Duplicates, late writes and races never turn SUCCESS/FAILURE back into a non-final state; duplicates are counted once.
3. **Exactly-once for dependents.** Callbacks, chain steps and fan-in bodies fire once, with results in header order, even under redelivery, duplicate reports and worker death.
4. **Bounded everything.** Retries, waits, queues of ids, buffers, memory growth, payload sizes, and shutdown all have limits and deadlines; failures in cleanup never become worker crashes.
5. **Fail loud on configuration, quiet on hazards.** Bad config errors at startup with a message naming the setting; expected hazards (missing result, already-gone cancel) are no-ops.
6. **Real elapsed time.** Delays, expiry, schedules and stall checks use real time across DST and time zones, and never trust remote clocks.
7. **Resources are released.** Connections, sockets, timers, subscriptions and files are closed on stop and reconnect, even when something else fails first; no per-cycle leaks.
8. **Secrets never leak** in logs, reports, URLs or errors.
9. **Same behaviour in every mode:** inline/eager, serialized round trip, other thread, mixed worker versions, SQLite vs PostgreSQL.
