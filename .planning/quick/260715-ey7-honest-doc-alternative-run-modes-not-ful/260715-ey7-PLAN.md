<objective>
Create an honest, evidence-based document enumerating sqlery's alternative execution/run
modes that are not fully implemented or tested, with per-mode status of implementation and
test coverage across both integration modes (Django, standalone) and both DBs (SQLite,
PostgreSQL) where relevant.

Purpose: The project claims "Feature-Complete Run Modes" as its goal, but several modes
(middleware daemon, django_tasks backend, Lambda/serverless, HTTP trigger, HTTP-trigger
middleware, async worker, sync thread mode) have uneven implementation and coverage. A
maintainer needs one truthful reference stating exactly what works, what is untested, and
what is aspirational. Honesty is the point — understating is acceptable, overstating is not.

Output: docs/internal/RUN_MODES_STATUS.md — a single markdown document with per-mode
sections, each citing the source files that implement the mode and the test files (or
explicit "NO TESTS FOUND") that cover it, plus whether those tests run in CI.
</objective>
