<task type="auto">
  <name>Task 2: Write coverage config in pyproject.toml + strict CI step</name>
  <files>pyproject.toml, .github/workflows/test.yml</files>
  <read_first>
    - pyproject.toml (full file — find a clean insertion point after `[tool.pytest.ini_options]`)
    - .github/workflows/test.yml (current coverage step)
  </read_first>
  <action>
    1. Add to `pyproject.toml`:
       ```toml
       [tool.coverage.run]
       source = ["src/sqlery"]
       branch = false
       omit = [
         "*/migrations/*",
         "*/templates/*",
         "**/stubs/*",
         "*_compat.py",
         "src/sqlery/lambda_handler.py",
       ]

       [tool.coverage.report]
       fail_under = 70
       show_missing = true
       skip_covered = false
       precision = 1
       exclude_lines = [
         "pragma: no cover",
         "raise NotImplementedError",
         "if TYPE_CHECKING:",
         "if __name__ == .__main__.:",
       ]
       ```

    2. Update `.github/workflows/test.yml` SQLite job (the one that runs the bulk of tests) to:
       ```yaml
       - name: Run tests with coverage
         run: uv run pytest tests/ -m "not postgres" \
                --cov=src/sqlery \
                --cov-report=term-missing \
                --cov-report=html \
                --cov-fail-under=70

       - name: Upload coverage HTML
         if: always()
         uses: actions/upload-artifact@v4
         with:
           name: coverage-html
           path: htmlcov/
           retention-days: 14
       ```
       Remove any preexisting `|| true` style tolerance. The threshold lives in BOTH `pyproject.toml` AND the CLI flag (belt-and-suspenders; CLI flag is authoritative because it's harder to miss in a review).

    3. The Postgres job (from 03-07) does NOT need its own coverage gate — coverage is measured on the SQLite job to keep the signal stable. Leave it without `--cov-fail-under`.
  </action>
