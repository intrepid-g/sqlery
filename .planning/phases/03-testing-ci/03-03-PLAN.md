<objective>
Build the foundational unit-test layer for the three framework-agnostic core modules (`core/claiming.py`, `core/worker.py`, `core/daemon.py`). Per RESEARCH, today's coverage is "indirect only" — these modules are touched by integration tests but have no focused unit suite. Per CONTEXT decision C the project-wide coverage gate lands at 70% in 03-08; these three plans (03-03..05) supply the missing direct coverage.

The cornerstone of the plan is a `FakeBackend` that implements the `DatabaseBackend` ABC with in-memory dicts — letting us exercise `claiming`, `worker`, and `daemon` logic without spinning up Django or SQLAlchemy.

**Scope note (acknowledged):** FakeBackend is the largest single deliverable in this plan — it must implement the full `DatabaseBackend` ABC (30+ abstract methods, expected 300-500 LOC). This is intentionally absorbed into Task 1 rather than split, because partial-FakeBackend artifacts cannot be consumed by Tasks 2/3. If during execution the executor finds the plan is materially exceeding ~10 tasks of work (e.g., FakeBackend balloons past 700 LOC because hidden abstract methods surface), **log the deviation in `03-03-SUMMARY.md` rather than splitting mid-flight** — the deviation note will inform any follow-up gap-closure plan.

Purpose: Direct unit coverage for TEST-05, TEST-06, TEST-07.
Output: `tests/unit/` directory + three focused test modules + shared FakeBackend fixture.
</objective>
