<objective>
Wire the Django backend to the partition machinery and complete the operator metrics.
Three concerns addressed together because they all depend on _partitioned_pg() and
get_raw_cursor() from Plan 16-01:

1. cleanup_jobs: route to reclaim_drained_partitions when partitioned PG (D5 —
   destroy-by-default, document loudly); keep batched DELETE loop on SQLite (D6).
2. vacuum_database: skip VACUUM on sqlery_queued_job when partitioned (partition DROP
   leaves nothing to vacuum); keep VACUUM for other tables; keep full SQLite VACUUM.
3. Write-path items 7-11: cancel_job, mark_job_archived, cascade_ancestor_status,
   get_job_by_id, update_job_child_pid — add created_at to their id-only filters so
   PG prunes to one partition. get_job_by_id gets created_at from the job object already
   in hand from the claim path.
4. async_backend.py: mirror cleanup and vacuum changes.
5. Daemon stats: add the 4 remaining metrics (partition count, oldest undrained partition
   age, staging-table depth, maintenance-tick duration) to the existing maintenance tick
   block that already emits the DEFAULT-partition row count (R9 complete).

Purpose: After this plan, the Django backend actually uses the partition machinery end-to-
end: reclaim fires via cleanup, VACUUM no longer fights the partitioned table, every hot
UPDATE prunes to one partition, and operators see all 5 metrics.

Output: Updated backend.py (cleanup+vacuum routing + items 7-11), updated
async_backend.py (mirrored), updated daemon.py (4 new metrics).
</objective>
