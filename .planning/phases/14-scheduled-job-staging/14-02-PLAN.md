## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| staged payload → sqlery_queued_job | Payload is opaque JSON, treated at same trust level as existing queued job kwargs (no re-validation needed at promotion time — it was validated at enqueue time) |
| daemon config → config validation | Config values come from Django settings, not user-supplied HTTP input |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-03 | Tampering | promote_due_scheduled_jobs raw SQL | mitigate | All table/column identifiers use pgsql.Identifier (psycopg.sql); all values use %s parameterised binding. No f-string SQL interpolation. |
| T-14-04 | Repudiation | double-promote race | mitigate | SKIP LOCKED prevents two cursors from seeing the same row; pg_try_advisory_lock prevents two daemons from running the function concurrently (D9). |
| T-14-05 | Denial of Service | staging table unbounded growth | accept | Promotion runs every partition maintenance tick (every N minutes). Threshold is configurable. Unbounded growth requires the daemon to be completely dead for days — monitored via check_default_partition analog; out of scope for this plan. |
| T-14-SC | Tampering | npm/pip/cargo installs | accept | No new packages introduced in this plan. |
</threat_model>
