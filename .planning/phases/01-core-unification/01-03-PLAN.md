  <action>
    Create `tests/test_core_standalone.py` with a single test function `test_core_imports_without_django`.

    Implementation approach: use `subprocess.run` to spawn a fresh Python interpreter where `django` is forcibly blocked. Two viable techniques — pick the one that works in the project's CI runners:

    Option A (preferred — works even if django is installed in the test env): pass a `-c` script that installs a `MetaPathFinder` blocking `django` BEFORE attempting the core imports:
    ```
    code = '''
    import sys
    class _BlockDjango:
        def find_spec(self, name, path=None, target=None):
            if name == "django" or name.startswith("django."):
                raise ImportError(f"django blocked for test: {name}")
            return None
    sys.meta_path.insert(0, _BlockDjango())
    import sqlery.core
    import sqlery.core.claiming
    import sqlery.core.worker
    import sqlery.core.daemon
    import sqlery.core.db_resilience
    import sqlery.core.log_config
    import sqlery.core.model_utils
    import sqlery.core.daemon_runner
    import sqlery.core.worker_runner
    import sqlery.core.scheduler_tasks
    import sqlery.core.utils
    import sqlery.core.worker_pool
    print("OK")
    '''
    result = subprocess.run([sys.executable, "-c", code], capture_output=True, text=True, timeout=30)
    assert result.returncode == 0, f"stdout={result.stdout}\\nstderr={result.stderr}"
    assert "OK" in result.stdout
    ```

    Mark the test with `@pytest.mark.standalone` if the project uses marker-based selection (check conftest.py); otherwise no marker.

    Add a second test `test_db_resilience_retry_works_without_django` that runs the same subprocess pattern and additionally asserts `sqlery.core.db_resilience.retry_on_db_error` is importable and the decorator wraps a function. This proves Plan 01 Task 1's `_RETRYABLE_EXC` fallback path actually works at runtime in a Django-less interpreter.
  </action>
