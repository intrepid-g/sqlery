<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| daemon/worker process → lease table | Multiple processes race to claim the same queue lease — the atomicity boundary |
| queue_name (caller-supplied) → SQL | Queue names flow into WHERE/INSERT; must be parameterized |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-04 | Tampering / Race | `claim_queue_leases` / `_claim_one_lease` | mitigate | Atomic claim per dialect: Postgres `with_for_update(skip_locked=True)` row lock; SQLite version-CAS `update(...).where(version==current).where(expires_at<now)` checking `rowcount == 1`. Concurrent-claim test asserts exactly one winner. Prevents two daemons holding the same queue lease. |
| T-08-05 | Elevation of Privilege | lease take-over | mitigate | A live lease held by another `daemon_id` is never displaced — take-over only when `expires_at < now` or the row is already ours. Skip-live-lease test enforces this. |
| T-08-06 | Spoofing | renew/release by non-owner | mitigate | `renew`/`release` filter on `daemon_id == self` so a process cannot renew or delete another daemon's lease. Tests assert non-owner renew/release is a no-op. |
| T-08-07 | SQL Injection | queue_name in WHERE/INSERT | mitigate | All queries use parameterized SQLModel/SQLAlchemy ORM expressions (`select/update/delete` with bound values) — no string interpolation of `queue_name`. |
| T-08-08 | Repudiation / Integrity | partial commit on race | mitigate | Each claim commits atomically; `IntegrityError` on a racing insert is caught and treated as "lost the race" (return False), never a silent overwrite. |
| T-08-SC | Tampering | npm/pip/cargo installs | accept | No new packages (sqlmodel/sqlalchemy already present; CLAUDE.md "no new dependencies"). N/A. |
</threat_model>
