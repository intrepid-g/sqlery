<objective>
Prove PARITY-01 (failover: killing the lease leader → another worker schedules within one TTL)
and PARITY-04 (bare-worker E2E: cron fires with only `sqlery-worker` processes, no daemon)
across the integration/database matrix, generalizing the SQLite-proven Phase 9
`TestWorkerSchedulerElection` precedent to the full grid and adding the Postgres cells that
Phase 9 deferred.

The election + failover behaviors already shipped in Phase 9 (`WorkerProcess.run` per-queue
claim/renew/release + `run_due_tasks(queue_names=held)`). This plan adds the cross-matrix proofs
only — no production source changes.

Purpose: Make failover and bare-worker scheduling first-class, CI-gated, cross-backend proofs so a
regression in election or lease takeover fails the build on both SQLite and Postgres.
Output: A new `tests/test_parity_scheduler.py` module (PARITY-01 + PARITY-04, parametrized over the
`(integration, db)` axis with the PG-only marker) and an extension to `tests/chaos/test_lease_zombie.py`
adding the standalone-backend real-lease failover PG cell.
</objective>
