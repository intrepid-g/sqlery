<objective>
Prove the Phase 9 election wiring (Plan 01) with fast, deterministic unit tests against the in-memory `FakeBackend` (which already implements real per-queue lease semantics and `get_due_scheduled_tasks` in `tests/unit/conftest.py`). The headline test demonstrates ELECT-04: a bare `WorkerProcess` (no daemon anywhere) fires a due cron `ScheduledTask` for a queue it holds. Supporting tests pin the rest of the election contract: claim/renew each cycle (ELECT-01), fire-only-held-queues (ELECT-02), daemon/foreign-lease authority + TTL failover (ELECT-05, ELECT-06), unchanged job-claim path (ELECT-07), and release-on-shutdown (ELECT-03).

Purpose: Lock the election behavior so Phase 11's full `{Django, standalone} × {SQLite, Postgres}` parity matrix can build on a proven core contract. These tests are the in-process behavioral proof; the cross-matrix proof is explicitly deferred to Phase 11.

Output: A `TestWorkerSchedulerElection` test class in `tests/unit/test_worker.py`.

Scope boundary: Unit tests only, no DB and no cross-matrix runs (Phase 11). Do NOT test cron-semantics hardening — atomic enqueue+advance, drift, jitter, exactly-once-under-overlap (Phase 10). Tests must run in well under a few seconds total (drive the loop directly or for a bounded number of cycles; never sleep for a real TTL).
</objective>
