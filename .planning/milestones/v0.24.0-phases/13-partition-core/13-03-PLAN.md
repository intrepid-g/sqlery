    Test harness strategy: a MockCursor class that records SQL calls and returns
    pre-programmed result sets. No live PG or Django setup needed. Tests run with:
      pytest tests/test_partitioning.py -v

    MockCursor protocol:
    - cursor.execute(sql, params=None): records the call
    - cursor.fetchall() / cursor.fetchone(): returns pre-programmed rows
    - cursor.description: None (not used)
    - cursor can be configured per-test via a side_effect list or per-call return values

    Tests to implement:

    test_list_partitions_returns_name_and_upper_bound:
    - Mock cursor returns two pg_inherits rows: one with a TO ('2026-01-02') expression,
      one with 'DEFAULT' in the expression.
    - Assert _list_partitions returns [(name, datetime(2026,1,2,...)), (default_name, None)].
    - Confirms DEFAULT maps to None (skip-rule 1 source).

    test_reclaim_skips_default:
    - _list_partitions returns [(name, None)] — a DEFAULT partition.
    - Assert reclaim_drained_partitions returns 0 and no DROP SQL is executed.
    - Skip rule 1: upper_bound is None → skip.

    test_reclaim_skips_inside_retention_window:
    - _list_partitions returns [(name, datetime.now(UTC) - timedelta(days=1))] — 1 day old.
    - retention_str = "30 days".
    - Assert reclaim_drained_partitions returns 0, no DROP.
    - Skip rule 2: upper_bound > now - retention.

    test_backpressure_invariant_queued:
    - _list_partitions returns a partition with upper_bound well past retention.
    - The EXISTS query for queued/running rows returns True (live queued row present).
    - Assert reclaim_drained_partitions returns 0, no DROP, no DETACH.
    - Skip rule 3: back-pressure invariant (R4).

    test_backpressure_invariant_running:
    - Same as above but the live row has status 'running'.
    - Assert reclaim_drained_partitions returns 0.
    - Confirms both 'queued' AND 'running' trigger the invariant.

    test_reclaim_drops_drained_partition:
    - _list_partitions returns one partition outside retention with no live rows.
    - Assert reclaim returns 1 and the SQL call sequence is:
        1. DETACH PARTITION (contains "DETACH")
        2. DROP TABLE (contains "DROP")
      DETACH MUST precede DROP — assert call order.
    - Confirms reference behavior: DETACH → DROP order matches pgwq.sql intent (with
      sqlery's added DETACH step per constraints.md).

    test_reclaim_calls_archive_hook_before_drop:
    - Partition is drained and outside retention.
    - archive_hook is a MagicMock.
    - Assert archive_hook is called once AFTER detach, BEFORE drop.
    - Hook call order: DETACH → archive_hook → DROP.

    test_advisory_lock_loser_skips_without_ddl:
    - Mock cursor returns False for pg_try_advisory_lock.
    - Call ensure_future_partitions and reclaim_drained_partitions.
    - Assert neither function executes any CREATE or DROP/DETACH SQL.
    - Assert both return 0.
    - Proves R8: two concurrent daemons (one wins lock, one loses) cause zero DDL conflicts.

    test_ensure_future_partitions_creates_premake_plus_one:
    - Mock: pg_try_advisory_lock returns True; CREATE TABLE IF NOT EXISTS never errors.
    - Call ensure_future_partitions(cur, "sqlery_queued_job", "1 day", premake=3).
    - Assert 4 CREATE statements issued (current + 3 future = premake+1).

    test_ensure_future_partitions_catches_attach_conflict:
    - Mock: pg_try_advisory_lock returns True; first CREATE raises psycopg.DatabaseError
      (simulating the attach-conflict error from rows in DEFAULT overlapping the range).
    - Assert function does NOT re-raise — returns normally (returns count of non-errored creates).
    - Assert a WARNING is logged (use caplog or monkeypatching).
    - Proves: ensure_future_partitions never wedges the maintenance loop.

    test_check_default_partition_returns_count_and_logs_warning:
    - Mock: _list_partitions-equivalent returns a DEFAULT partition row.
    - COUNT(*) query returns 5.
    - Assert check_default_partition returns 5.
    - Assert a WARNING log containing "DEFAULT partition" and "5" is emitted (use caplog).
    - Proves R9: DEFAULT-partition alert fires when count > 0.

    test_check_default_partition_returns_zero_when_empty:
    - COUNT(*) returns 0.
    - Assert function returns 0. No WARNING logged.

    test_validate_maintenance_interval_rejects_oversized_interval:
    - _validate_partition_maintenance_interval(2000, "1 day") raises ValueError.
    - _validate_partition_maintenance_interval(5, "1 day") does not raise.
    - _validate_partition_maintenance_interval(60, "1 hour") does not raise.
    - _validate_partition_maintenance_interval(61, "1 hour") raises ValueError.
