### FIX-1: 0029 — replace broken identity-sequence wiring with standalone sqlery_job_id_seq

**Files modified:** `src/sqlery/django_sqlery/migrations/0029_scheduled_job_staging.py`
**Commit:** cf50b85
**Applied fix:**
- Created standalone sequence `sqlery_job_id_seq` (owned by nothing, survives renames)
- Dropped `GENERATED AS IDENTITY` from `sqlery_queued_job.id` and `sqlery_scheduled_job.id`
- Set `DEFAULT nextval('sqlery_job_id_seq')` on both columns
- Seeded the sequence past `MAX(id)` of `sqlery_queued_job` using `setval(..., GREATEST(...), is_nonempty)`
- Commented out old (broken) lines: `ALTER SEQUENCE ... OWNED BY NONE`, `DROP SEQUENCE sqlery_scheduled_job_id_seq`, `nextval('sqlery_queued_job_id_seq')` — those relied on ordinary named sequences but Django creates identity sequences for `BigAutoField` on PG
- Updated reverse SQL: drops defaults from both tables, restores `ADD GENERATED BY DEFAULT AS IDENTITY` on `sqlery_queued_job`, drops `sqlery_job_id_seq`

### FIX-2: 0030 S4 — remove ADD GENERATED BY DEFAULT AS IDENTITY step

**Files modified:** `src/sqlery/django_sqlery/migrations/0030_partition_queued_job.py`
**Commit:** 2479cba
**Applied fix:**
- Commented out the entire S4 block (`attidentity` check + `ALTER TABLE ... ADD GENERATED BY DEFAULT AS IDENTITY`)
- After 0029, `sqlery_queued_job.id` already carries `DEFAULT nextval('sqlery_job_id_seq')`. Step S2 uses `LIKE ... INCLUDING DEFAULTS`, so the new partitioned table inherits that default automatically. Re-adding IDENTITY would create a conflicting per-table identity sequence and break the shared-sequence invariant.

### FIX-3: 0030 S6 and S9 — fix index name collision and setval target

**Files modified:** `src/sqlery/django_sqlery/migrations/0030_partition_queued_job.py`
**Commit:** 2479cba (same commit as FIX-2)
**Applied fix — S6:**
- The S1 rename moves `sqlery_job_pending_idx` from `sqlery_queued_job` to `sqlery_queued_job_legacy`. `CREATE INDEX IF NOT EXISTS` then sees the name already exists (on the legacy table) and silently skips — leaving the partitioned table without the index.
- Fix: `DROP INDEX IF EXISTS sqlery_job_pending_idx` first, then `CREATE INDEX sqlery_job_pending_idx ON sqlery_queued_job ...` (without IF NOT EXISTS).

**Applied fix — S9:**
- `pg_get_serial_sequence('sqlery_queued_job', 'id')` only works for `GENERATED AS IDENTITY` or `SERIAL` columns. After 0029, `id` is a plain `DEFAULT nextval(...)` column, so `pg_get_serial_sequence` returns `NULL` and `setval(NULL, ...)` raises an error.
- Fix: seed `sqlery_job_id_seq` directly: `SELECT setval('sqlery_job_id_seq', GREATEST((SELECT COALESCE(MAX(id),0) FROM sqlery_queued_job), 1), (SELECT COUNT(*)>0 FROM sqlery_queued_job))`
