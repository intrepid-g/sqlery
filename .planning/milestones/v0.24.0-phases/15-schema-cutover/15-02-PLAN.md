    S7 — Historical partitions BEFORE the bulk copy (prevents DEFAULT-partition trap — finding #2):
      Emit partitions from date_trunc('day', min(created_at)) on the legacy table through

        cursor.execute("SELECT MIN(created_at), MAX(created_at) FROM sqlery_queued_job_legacy")
        min_ts, max_ts = cursor.fetchone()
        If min_ts is None (empty table), skip the loop.
        Otherwise:
          from datetime import datetime, timedelta, timezone
          import math
          # Round down to day boundary
          start = min_ts.replace(hour=0, minute=0, second=0, microsecond=0, tzinfo=timezone.utc)
          # Include today + PREMAKE days ahead
          PREMAKE = 7
          end = datetime.now(timezone.utc).replace(hour=0, minute=0, second=0, microsecond=0) + timedelta(days=PREMAKE + 1)

              partition_name = "sqlery_queued_job_" + current.strftime("%Y%m%d")

                  " FOR VALUES FROM (%%s) TO (%%s)" % partition_name,

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Migration DDL → live PG schema | Stop-the-world window; writes between rename and copy end would be lost |
| Partition name string → SQL | Partition names are date-derived (digits+underscore only) — no untrusted interpolation |
| setval target | Max(id) from the copied table — internal data, no external input |
| Rollback path | Reverse SQL copies from live partitioned table back to unpartitioned — same stop-the-world assumption |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-05 | Denial of service | Stop-the-world window: live writes during rename → copy lose data | mitigate | D3: operational protocol requires workers/daemons stopped before migration; documented in migration docstring |
| T-15-06 | Tampering | Partial migration failure (atomic=False) leaves schema in intermediate state | mitigate | Every statement idempotent: to_regclass rename guard, IF NOT EXISTS for table/index/partition, ON CONFLICT DO NOTHING for copy; recovery = rerun |
| T-15-07 | Tampering | DEFAULT partition trap: rows landing in DEFAULT after migration | mitigate | Historical partition loop in S7 runs BEFORE S8 bulk copy; zero-DEFAULT-rows verified in 15-03 SC2 test |
| T-15-08 | Tampering | Identity gap: new rows get id lower than existing rows (sequence not reseeded) | mitigate | S9 setval past max(id) in copied rows; verified in 15-03 SC3 test |
| T-15-09 | Tampering | Index name collision: sqlery_job_pending_idx already exists from 0028 | mitigate | CREATE INDEX IF NOT EXISTS skips creation if already attached to partition; byte-identical definition (D7) prevents divergence |
| T-15-10 | Spoofing | SQL injection via partition name | accept | Partition names are derived from date_trunc arithmetic (YYYY + MM + DD digits only) — no external input reaches the name |
| T-15-SC | Tampering | Package installs | accept | No new package installs in this migration — pure stdlib + existing psycopg cursor |
