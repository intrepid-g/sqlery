## Phase Boundary

The partition cutover itself (ingest Phase 4; **PLAN.md Steps 7–8**). Depends on Phases 13–14. **HIGHEST-RISK phase of the milestone; its verification gates Phases 16–18.**

- **Blast-radius audit FIRST (precondition, Step 7):** grep both adapters and tests for `.pk`, `pk=`, `pk__in`, `refresh_from_db`, `in_bulk`, and FK traversals of `QueuedJob`. Known hit: `save_meta` filters `filter(pk=self.pk)` at `models.py:823` — `.pk` becomes a tuple under a composite PK; rewrite as `filter(id=self.id, created_at=self.created_at)`. Zero unaddressed hits is an acceptance criterion.
- **Composite PK (Step 7):** `pk = models.CompositePrimaryKey("created_at", "id")`; `id = models.BigAutoField(primary_key=False)` (Django 5.2, already required). Demote `JobRegistry.job` and `Worker.current_job` FKs to plain indexed `BigIntegerField` (`parent_job_id` is already a plain int). Version-based optimistic locking is unaffected (filters on `id` + `version`, never `pk`) — but verify the SQLite path in tests.
- **Migration `0029_partition_queued_job.py` (Step 8, `atomic=False`, PG-only — no-op on SQLite):** guarded idempotent rename → `CREATE TABLE … (LIKE … INCLUDING DEFAULTS INCLUDING STORAGE)` (NOT INCLUDING IDENTITY) `PARTITION BY RANGE (created_at)` → `ADD PRIMARY KEY (created_at, id)` → `ADD GENERATED BY DEFAULT AS IDENTITY` → DEFAULT partition → the Phase-12 partial index VERBATIM → **historical partitions created BEFORE the bulk copy** (one per interval from `date_trunc('day', min(created_at))` through `now() + premake`) → `INSERT … SELECT … ON CONFLICT DO NOTHING` → `setval` past max(id). `state_operations` mirror the Step 7 model changes. Legacy table dropped only in a separate LATER migration so rollback is a rename, not a copy.

**Mapped requirements:** R6 (REQ-single-partition-writes — schema half; write-path filters complete in Phase 16), R7 (REQ-migration-rollback).

<decisions>
## Implementation Decisions (LOCKED — do not re-ask, do not re-litigate)

- **D3 — Stop-the-world migration:** stop all workers/daemons, run 0029, restart. No online dual-write cutover. Document expected duration as a function of table size. Escape hatch for huge tables: run the SQL manually during a maintenance window, then `migrate --fake` this specific migration (NOT `--fake-initial`).
- **D4 — FK referential integrity to jobs is dropped:** `JobRegistry.job` and `Worker.current_job` become plain indexed `BigIntegerField`; orphans on partition drop are an accepted, documented trade-off.
- **D7 — Index byte-identity:** the 0029 DDL recreates `sqlery_job_pending_idx` exactly as Phase 12's 0028 definition — `(queue_name, priority DESC, created_at) WHERE status = 'queued'`. Intentional churn; safe only because the definitions are byte-identical. If either changes, change both.
- **D8 — Existing installs partition on migrating; new PG installs partition by default.** No feature flag for partitioning itself.
- **D10 — Phase ordering fixed.**

## Success Criteria (verbatim from GSD-CONTEXT.md Phase 4)

1. Migration round-trip (legacy → partitioned → rollback) passes on a generated production-sized snapshot (≥1M rows).
2. Zero rows in DEFAULT after migration.
3. Identity continues from max(id)+1.
4. Re-running the migration after an injected mid-migration failure completes cleanly.
5. The `.pk` audit has zero unaddressed hits.

## Verification Anchors (from intel/constraints.md)

- Test matrix item owned here: migration round-trip on a production-sized snapshot (legacy → partitioned → rollback).
- Every 0029 statement idempotent (`IF NOT EXISTS`, guarded rename) — partial failure under `atomic=False` is recoverable by re-running.
- Rollback is the reverse swap (create unpartitioned `LIKE` table, copy back, rename); keep the legacy table until the new path has soaked — `DROP TABLE … _legacy` is a separate later migration.
- Migration is a no-op on SQLite (`connection.vendor` guard) — R10's cutover half.
- Operational protocol: documented maintenance window + `migrate --fake` escape hatch.
