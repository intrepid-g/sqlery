    Test structure (each test is a function; use pytest, not unittest):

    test_snapshot_generation:
      - Connects to SQLERY_TEST_PG_URL; skips if env var not set
      - Runs the legacy-schema setup (unpartitioned sqlery_queued_job with all real columns,
        matching the pre-migration schema read from 0029_scheduled_job_staging or legacy DDL)
      - Inserts ≥1M rows using a single INSERT...SELECT generate_series statement (fast, no Python loop)
      - Asserts row count >= 1_000_000 (SELECT COUNT(*))
      - Leaves the snapshot in place for subsequent tests (session-scoped fixture or explicit setup)

    test_migration_forward_sc1_sc2_sc3:
      - Requires snapshot in place (≥1M rows in sqlery_queued_job or equivalent legacy table)
      - Calls _VendorGuardedCutover._forward(connection) directly (unit-style, no Django migrate command)
      - SC1: queries SELECT COUNT(*) FROM sqlery_queued_job and asserts count >= 1_000_000
      - SC2: queries the DEFAULT partition row count (use check_default_partition or equivalent
        direct SQL: SELECT COUNT(*) FROM sqlery_queued_job_default); asserts == 0
      - SC3: inserts one more row, reads its id, asserts id > (SELECT MAX(id) FROM sqlery_queued_job)
        before the insert (i.e. identity continues monotonically past the copied max)

    test_migration_rollback:
      - Calls _VendorGuardedCutover._backward(connection) directly
      - Asserts sqlery_queued_job exists as an unpartitioned table (check pg_class.relkind != 'p')
      - Asserts row count equals the pre-rollback count (≥1M)
      - Asserts sqlery_queued_job_legacy still exists (kept per D3)

    test_migration_idempotency_sc4:
      - Sets up a fresh legacy table with a small row count (1000 rows is sufficient)
      - Injects a mid-migration failure by:
          a. Starting a transaction
          b. Executing S1 (rename guard) directly
          c. Rolling back / raising an exception to simulate a crash after rename but before copy
          d. Verifying sqlery_queued_job_legacy exists but sqlery_queued_job has 0 rows (or may not exist)
      - Then calls _VendorGuardedCutover._forward(connection) a SECOND time (the rerun)
      - Asserts it completes cleanly (no exception) and the row count is correct
      - This proves idempotency: a partial failure followed by a full rerun converges to the correct state

    Skipping: all tests must be decorated with:
      @pytest.mark.skipif(
          not os.environ.get("SQLERY_TEST_PG_URL"),
          reason="SQLERY_TEST_PG_URL not set — skipping PG-only round-trip test"
      )

    Connection management: use psycopg.connect(os.environ["SQLERY_TEST_PG_URL"], autocommit=True)
    for DDL statements. Use a separate function-scoped fixture that sets up and tears down

    Snapshot generation SQL (fast path, avoids Python loop):
      INSERT INTO sqlery_queued_job (task_path, kwargs, queue_name, status, created_at, priority)
      SELECT
          'myapp.tasks.task_' || (i % 100)::text,
          '{}'::jsonb,
          'default',
          CASE WHEN i % 5 = 0 THEN 'success' ELSE 'queued' END,
          now() - ((1000000 - i) * interval '1 second'),
          0
      FROM generate_series(1, 1000000) AS s(i);

    This spreads created_at across roughly 11 days so historical partitions cover the range.
