class TestListenNotifyLatencyPG:
  These tests require SQLERY_TEST_PG_URL and verify sub-100ms dispatch.

  test_dispatch_latency_under_100ms_django:
    Strategy: run a real WorkerProcess._wait_for_notify() in a background thread, then
    call notify_queue_django (or directly call pg_notify via a psycopg connection), and
    measure the wakeup latency.

    Full integration approach (avoids full run() complexity):
    1. Open a psycopg3 AUTOCOMMIT connection to SQLERY_TEST_PG_URL.
    2. Create a WorkerProcess-like harness:
       - Set self._listen_conn to a psycopg3 connection LISTENing on
         sanitize_queue_name_to_channel('default').
       - Set self.poll_interval = 5 (would block 5s without NOTIFY).
       - Set self.shutdown_requested = False.
       - Set self._heartbeat_due = False.
       - self._check_heartbeat = lambda: None (no-op).
    3. In a background thread: call worker._wait_for_notify(). Thread blocks up to 5s.
    4. In the main thread: sleep 20ms (enough for thread to enter notifies()), then:
       - Open a second psycopg3 AUTOCOMMIT connection to SQLERY_TEST_PG_URL.
       - Execute SELECT pg_notify(%s, '') with [sanitize_queue_name_to_channel('default')].
       - Record t0 = time.monotonic() before notify.
    5. Join the background thread with timeout=0.5.
    6. Record t1 = time.monotonic() after join.
    7. Assert (t1 - t0) < 0.100 (sub-100ms dispatch latency).

    To use a minimal WorkerProcess-like object without full Django initialization,
    instantiate a simple namespace or a partial WorkerProcess:
    - Create a test-harness class TestListenWorker with only the attributes and methods
      needed by _wait_for_notify (_listen_conn, poll_interval, shutdown_requested,
      _heartbeat_due, _check_heartbeat). This avoids calling get_backend() in __init__.
    OR use unittest.mock.MagicMock for the backend and call WorkerProcess.__new__(WorkerProcess)
    then manually set the required attributes before calling _wait_for_notify().

    Use `psycopg.connect(SQLERY_TEST_PG_URL, autocommit=True)` for both connections.
    Skip test if psycopg import fails (guard: try import psycopg; except ImportError: pytest.skip).

  test_flag_off_no_listen_connection_pg:
    @_SKIP_NO_PG
    Verify that even on a real PG database, when SQLERY_PG_NOTIFY=False,
    _open_listen_conn sets self._listen_conn = None.
    - Construct a minimal WorkerProcess (mock backend).
    - Patch get_config to return False for SQLERY_PG_NOTIFY.
    - Call _open_listen_conn().
    - Assert self._listen_conn is None.
    - Assert no psycopg.connect was called (mock psycopg.connect and assert not called).

  test_sqlite_no_notify_emitted_on_enqueue:
    (Uses Django SQLite test DB — no SQLERY_TEST_PG_URL needed)
    This asserts that a create_job call on the Django test runner's SQLite DB does NOT
    call pg_notify even if SQLERY_PG_NOTIFY is patched to True.
    - Patch get_setting to return True for SQLERY_PG_NOTIFY.
    - Patch _notify_queue_django sentinel in backend module.
    - Call DjangoBackend().create_job with basic args.
    - Assert the sentinel was NOT called (because connection.vendor == 'sqlite3').
