<objective>
Integrate the LISTEN wake-up into WorkerProcess.run() poll loop idle sleep.

Purpose: When SQLERY_PG_NOTIFY is enabled and the backend is PostgreSQL, the worker
opens a dedicated psycopg3 connection in AUTOCOMMIT mode, executes LISTEN on all its
queues' channels, then waits on conn.notifies(timeout=...) during the idle sleep
instead of time.sleep(1). On NOTIFY arrival the loop exits immediately to claim.
On timeout it falls back to the normal claim attempt. When flag off or SQLite, the
idle sleep block is byte-identical to today's implementation.

Fork-safety: the LISTEN connection is registered as a pre_fork hook on ForkSafeExecutor
so it is closed before os.fork() and re-opened by the parent after fork. The child
never inherits the connection.

Signal-handler constraint (CLAUDE.md): the SIGUSR1 heartbeat handler sets only
self._heartbeat_due = True — no DB calls. The LISTEN connection interacts with the
poll loop body only, never signal handlers.

Output: Modified src/sqlery/core/worker.py only.
</objective>
