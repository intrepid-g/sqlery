# Requirements: Sqlery v1.0 — Feature-Complete Run Modes (ARCHIVED)

> **Milestone status:** ✅ Shipped 2026-05-15. All 43 requirements verified.
> See `v1.0-ROADMAP.md` for the phase-level archive and `.planning/v1.0-MILESTONE-AUDIT.md` for the audit report.

**Defined:** 2026-05-12
**Core Value:** Every execution mode works reliably and is tested in CI across both Django and standalone integration modes, on both SQLite and PostgreSQL.

## v1 Requirements

### Code Unification

- [x] **UNIF-01**: Claiming algorithm consolidated — `django_sqlery/worker_claiming.py` delegates to `core/claiming.py` via backend abstraction
- [x] **UNIF-02**: Execution logic consolidated — `django_sqlery/executor.py` delegates to `core/worker.py` JobExecutor via DjangoBackend
- [x] **UNIF-03**: Django imports removed from `core/` package — all 8 affected modules route through compat layer or try/except guards
- [x] **UNIF-04**: `core/worker.py` works without Django installed (standalone mode)
- [x] **UNIF-05**: `core/daemon.py` works without Django installed (standalone mode)
- [x] **UNIF-06**: `core/db_resilience.py` works without Django installed (standalone mode)

### Execution Modes — Django

- [x] **DMOD-01**: Daemon mode passes E2E test (enqueue → claim → execute → complete) in Django
- [x] **DMOD-02**: Subprocess mode passes E2E test in Django
- [x] **DMOD-03**: HTTP trigger mode passes E2E test in Django
- [x] **DMOD-04**: Lambda/serverless mode passes E2E test in Django (mocked Lambda invocation)
- [x] **DMOD-05**: Synchronous/thread mode passes E2E test in Django
- [x] **DMOD-06**: Async worker mode passes E2E test in Django

### Execution Modes — Standalone

- [x] **SMOD-01**: Daemon mode passes E2E test in standalone (FastAPI/SQLAlchemy)
- [x] **SMOD-02**: Subprocess mode implemented and passes E2E test in standalone
- [x] **SMOD-03**: HTTP trigger mode implemented and passes E2E test in standalone
- [x] **SMOD-04**: Lambda/serverless mode implemented and passes E2E test in standalone
- [x] **SMOD-05**: Synchronous/thread mode passes E2E test in standalone
- [x] **SMOD-06**: Async worker mode implemented with real async backend (asyncpg/aiosqlite) and passes E2E test

### Async Worker Rebuild

- [x] **ASYN-01**: Async DatabaseBackend ABC defined in compat layer with all required methods
- [x] **ASYN-02**: Async Django backend implementation (wrapping sync ORM or using async ORM)
- [x] **ASYN-03**: Async SQLAlchemy backend implementation (using asyncpg/aiosqlite)
- [x] **ASYN-04**: AsyncWorker class refactored to use new async backend
- [x] **ASYN-05**: Async worker supports graceful shutdown via signal handling

### Testing

- [x] **TEST-01**: E2E integration tests for each execution mode in Django (6 modes × enqueue/claim/execute/complete)
- [x] **TEST-02**: E2E integration tests for each execution mode in standalone (6 modes)
- [x] **TEST-03**: Edge case tests: job timeout, worker crash recovery, retry logic, concurrent workers
- [x] **TEST-04**: Edge case tests: zombie job detection, stale heartbeat cleanup, queue lease expiry
- [x] **TEST-05**: Unit tests for core/claiming.py (tag concurrency, rate limits, dependencies, TTL expiry)
- [x] **TEST-06**: Unit tests for core/worker.py (fork lifecycle, signal handling, connection reset)
- [x] **TEST-07**: Unit tests for core/daemon.py (daemon lifecycle, scheduler integration, worker pool management)
- [x] **TEST-08**: Unit tests for fastapi_sqlery/backend.py (SQLAlchemyBackend — all 30+ DatabaseBackend methods)
- [x] **TEST-09**: Unit tests for django_sqlery/backend.py (DjangoBackend — all 30+ DatabaseBackend methods)
- [x] **TEST-10**: Unit tests for webhooks.py (HMAC signing, retry logic, HTTP delivery)
- [x] **TEST-11**: PostgreSQL-specific tests in CI for all modes (not just 2 files)
- [x] **TEST-12**: CI workflow triggers fixed (master → main branch)

### Security

- [x] **SEC-01**: FastAPI standalone dashboard has authentication (API key or basic auth middleware)
- [x] **SEC-02**: Webhook URLs validated against SSRF — private/link-local IP ranges blocked
- [x] **SEC-03**: Django admin API endpoints have CSRF protection or token-based auth
- [x] **SEC-04**: `ALLOWED_TASK_MODULES` config option restricts importable task paths

### Cleanup

- [x] **CLEAN-01**: 24 backward-compatibility stub files marked for removal (commented with deletion date)
- [x] **CLEAN-02**: Dead AsyncStorageBackend = None code marked for removal (after async rebuild replaces it)
- [x] **CLEAN-03**: Commented-out code blocks throughout codebase marked with deletion dates
- [x] **CLEAN-04**: Webhook import bug fixed (`django_sqlery.webhooks` → `sqlery.webhooks`)

## v2 Requirements

### Performance

- **PERF-01**: PostgreSQL LISTEN/NOTIFY for instant job wakeup (replaces polling)
- **PERF-02**: TTL expiry moved from claiming hot path to periodic daemon cleanup
- **PERF-03**: Job result size limits to prevent database bloat

### Operational

- **OPS-01**: API endpoint rate limiting (FastAPI and Django)
- **OPS-02**: Job result size limits configuration
- **OPS-03**: Connection pooling for standalone mode forked workers (NullPool or re-init after fork)

### Documentation

- **DOC-01**: Execution modes documented with configuration examples
- **DOC-02**: Migration guide for each mode (from RQ, Celery, django-tasks-scheduler)
- **DOC-03**: Security model documentation

## Out of Scope

| Feature | Reason |
|---------|--------|
| Redis/RabbitMQ backends | Sqlery is database-backed by design |
| Mobile/desktop clients | This is a Python library |
| Dashboard UI redesign | Existing dashboards get auth, not a rewrite |
| Multi-tenancy | Library for single-project use |
| New trigger modes beyond 6 | Future milestone |
| Immediate deletion of dead code | User prefers comment-and-date-mark approach |
