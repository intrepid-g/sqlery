## 3. End-to-End Flow Traces

### Flow A — Django daemon mode (DMOD-01)

`@job` decorator (`core/job.py`) → `enqueue()` (`core/job_queue.py`) → `DjangoBackend.enqueue_job` → daemon (`django_sqlery/management/commands/daemon.py`) spawns `WorkerProcess` (`core/worker.py`) → `claim_next_job_with_queue_priority(worker, backend, queues)` (Phase 03 GAPS + Phase 04-01 arity fix) → SEC-04 `check_task_module_allowed` gate → `import_task` → `JobExecutor.execute_job` → terminal write. **Verified end-to-end via `tests/integration/test_modes.py` (daemon, django) cell.**

### Flow B — Standalone subprocess mode (SMOD-02)

`enqueue()` → `SQLAlchemyBackend.enqueue_job` → `fastapi_sqlery/subprocess_executor.py:65 spawn_subprocess_worker` → child process imports `core.worker`, runs `JobExecutor.execute_job` with SEC-04 gate → result row. SSRF gate not on this path. Auth gate (SEC-01) protects the `/trigger` endpoint that could enqueue from outside — verified wired before router. **Verified via `conftest.py:380 _drive_subprocess_standalone` + parametrized cell.**

### Flow C — Async worker graceful shutdown (ASYN-05)

`AsyncWorker.start()` registers `asyncio.add_signal_handler` for SIGTERM/SIGINT (not `signal.signal` — guarded by `test_uses_add_signal_handler_not_signal_signal`). On signal: `_shutting_down=True`, current `_drain_one` task → `aget_job` → `amark_shutting_down(job_id)` (line 384, writes transient state to DB) → `asyncio.wait(task, deadline=60s)` (line 390) → terminal write overwrites transient state. Schema support via Django migration `0026_add_shutting_down_status.py` and Alembic `20260514_0014_add_shutting_down_status.py`. **Verified by 18/18 dedicated shutdown tests + Phase 02 gate greps re-run.**
