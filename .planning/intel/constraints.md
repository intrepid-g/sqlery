## Config contract [type: api-contract]

New keys (Django `DJANGO_SQL_JOBS` defaults + `fastapi_sqlery/config.py` mirror):

- `SQLERY_PARTITION_INTERVAL` = `"1 day"` — partition width
- `SQLERY_PARTITION_PREMAKE` = `7` — future partitions kept ready
- `SQLERY_PARTITION_RETENTION` = `"30 days"` — min age before a drained partition may drop
- `SQLERY_PG_NOTIFY` = `False` — opt-in LISTEN/NOTIFY (only flagged feature)
- `SQLERY_PARTITION_ARCHIVE_HOOK` = `None` — optional callable per detached partition before DROP
- `PARTITION_MAINTENANCE_INTERVAL_MINUTES` = `5` — daemon maintenance cadence
- Staging threshold = 1 day (jobs with `scheduled_at > now() + threshold` go to staging)

Validation invariants at config load:
- `SQLERY_PARTITION_RETENTION` must be ≫ staging threshold (reject retention ≤ threshold)
- `PARTITION_MAINTENANCE_INTERVAL_MINUTES` must be ≤ `SQLERY_PARTITION_INTERVAL`

## Schema / SQL contracts [type: schema]

- Pending index DDL, byte-identical in migration 0028 and migration 0029:
  `(queue_name, priority DESC, created_at) WHERE status = 'queued'`, name
  `sqlery_job_pending_idx`. If either definition changes, change both.
- Status literal `'queued'` (models.py:351); claim ordering `-priority, created_at`
  (backend.py:870-874).
- Composite PK `(created_at, id)`; `id` stays `BigAutoFIELD(primary_key=False)`-style
  identity, globally unique via one shared sequence (shared with the staging table).
- Migration 0029: every statement idempotent (`IF NOT EXISTS`, guarded rename);
  `LIKE … INCLUDING DEFAULTS INCLUDING STORAGE` (NOT INCLUDING IDENTITY);
  `ADD GENERATED BY DEFAULT AS IDENTITY` + `setval` past max(id); historical partitions
  created BEFORE the bulk copy; DEFAULT partition exists; legacy table dropped only in a
  separate later migration (rollback = rename).
- Migration numbering: latest existing is 0027 (verified in repo); new ones are
  0028 (partial index), 0029 (partition cutover), 0030 (staging table).
- `core/partitioning.py` takes a raw cursor; no Django or SQLAlchemy imports.

## Operational constraints [type: protocol]

- Migration 0029 is stop-the-world: stop all workers/daemons, run, restart. Document
  expected duration as a function of table size. Escape hatch: manual SQL + `migrate --fake`.
- All partition DDL and promotion guarded by `pg_try_advisory_lock`; lock loser skips
  the tick silently.
- `ensure_future_partitions` must catch the attach-conflict error (rows in DEFAULT
  overlapping a new range) and alert instead of wedging the maintenance loop.
- Reclaim order: DETACH PARTITION first (shrinks lock window) → archive hook → DROP.
- Rows in DEFAULT partition > 0 is a standing alert (never reclaimed; blocks future
  partition creation).
